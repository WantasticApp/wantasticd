# Implementation status

| Area | Status |
| --- | --- |
| SwiftUI menu bar and main window | Native menu-bar controls, device/network/settings workspaces, and a first-class Console workspace are implemented. Console content is rendered in a persistent native WKWebView with back/forward/reload and open-in-browser controls. Live WebKit login/SSO, signed-extension tunnel activation, and interactive UI behavior still require runtime verification on a fully provisioned Mac |
| Device model and service labels | The app polls the provider for the Go-compatible P2P peer list and maps assigned overlay addresses into the device list. Explicit ping/chart and user-confirmed service scanning are present. Detected web, RDP, and SSH services expose native handler links built only from literal IP addresses and matching service ports. The native collector reports non-sensitive host/interface telemetry, including product version, uptime, memory, TCP implementation, local time/time zone, and IPv4/IPv6 capability, using Darwin APIs without shell commands or AppleScript. Friendly names and live production hub behavior remain unverified |
| Setup and credentials | RFC 8628 device-code request/polling, device registration/config decryption, Keychain persistence, and resume/clear UI. Manual WireGuard import now has an independent Keychain item and explicit profile source selector, preserving registered login credentials when setup methods change. Both paths configure the non-secret Network Extension profile and attempt connection. Connection requests ask macOS to activate the bundled system extension and surface approval/reboot outcomes. Live activation remains unverified without full Xcode, Apple-granted entitlements, and matching provisioning |
| App/extension credential boundary | Matching team-prefixed Keychain access group is declared and provider reads registration from the shared Keychain; signed cross-target access is not yet exercised |
| English, Spanish, Arabic, French, German | Every key in the app copy catalog is tested for a translation in all five languages; broader human copy review and RTL visual QA remain |
| WUSP | Version-1 transport envelope, compact selectors, inline-path WU typed-value frames, LZ4, Go-compatible type-8 control-fragment framing, bounded assembly, authenticated request/response correlation, timeout handling, and assembled inbound-control events implemented. The provider emits Go-contract OnBoardRequest notifications after tunnel establishment and re-announces every 45 seconds using a non-hardware-derived device identifier. A versioned, size-bounded app-to-provider RPC dispatches WUSP requests, P2P peer-list/direct requests, and exit-node selection/clear requests with stable errors; exit selection is rejected unless the selected peer advertises that capability. Inbound Get serves collected macOS host/interface values by Go selector or path; Go tests verify native telemetry selector IDs against the runtime model, and Swift exercises them through typed Get responses. GetInstances returns locally collected interface/address objects; Set/Delete cover Keychain-backed FriendlyName and ProvisioningCode. Mutating requests now use a bounded 256-entry, two-minute replay cache keyed by request ID and sequence, fingerprint request content while excluding the transport response budget, replay exact responses, coalesce concurrent retries, and reject reused identities with different action data, matching the Go runtime contract. Inbound Notify subscriptions support Go-compatible type/path filters, replace/unsubscribe semantics, success metadata, and ValueChange notifications over the authenticated tunnel. GetSupportedDM describes the supported macOS subset. Operate supports `Device.Reboot()` through a fixed certificate-pinned helper request and Darwin `reboot(RB_AUTOBOOT)` scheduled two seconds later, and `Device.FactoryReset()` by clearing only this console host's registered/manual tunnel and FriendlyName/ProvisioningCode Keychain items, then stopping the provider two seconds after a successful response. Factory reset leaves the non-secret Network Extension profile installed so setup can reuse it; deleting the profile was intentionally not conflated with clearing device credentials. No shell or caller-provided executable is used; other commands return WUSP_UNSUPPORTED. Upload/Download use authenticated raw type-8 sessions with sequence/offset checks, 1,120-byte chunks, bounded retry on missing ACKs, at most eight sessions, a 512-MiB per-transfer and aggregate staging quota, a 10-minute lifetime, atomic upload commit, and no overwrite. File access is confined to the extension's private Application Support transfer directory; there is no user-facing file import/export picker yet. Open/chunk codecs have Swift/Go byte-parity fixtures, including LZ4. Add, other Go operations, user-selected external-file access, and live tenant interoperability remain unverified |
| P2P coordination | Go-compatible message-6 registration/peer-list messages, WPC1 candidates, and bounded target generation are implemented. The provider validates relay peers, authenticates punches over up to 16 UDP flows reusing the coordinator local port, then attempts a fresh WireGuard handshake over the winning socket before marking a peer direct. IPv4 packets for an established direct peer use its peer-specific session; direct-send failure retires that path and retries the packet through the hub transport. Direct sessions are also retired after four minutes without a fresh authenticated handshake, matching the Go peer stale timeout; an authenticated rekey renews that deadline. Tests cover direct-send fallback, relay-failure propagation, fresh handshake promotion, stale-session retirement, and repeated rekeys renewing the deadline. Production hub/NAT behavior, packet-flow route changes, live-loss relay recovery, and independent-network traversal remain unverified. |
| TUN control payloads | Swift codec covers Go exit-node selection/offer and private IPv4 local-access advertisement/update/removal/snapshot payloads, with strict bounds, /32 support, and Go-padding-aware decoding. Go and Swift both consume `testdata/protocol/local_access_advertisement.hex` to assert identical type-7 advertisement bytes. The UI only exposes exit-node selection for peers advertising that capability, and the provider rechecks the peer snapshot before sending the Go-compatible type-7 selection. Authenticated hub type-7 select/revoke controls install/remove the corresponding IPv4/IPv6 default routes using Go's address-family policy; route-builder and RPC integration tests cover these paths. The provider applies remote local-route updates by advertiser and rolls back state if macOS rejects settings. The explicit local-access UI now selects discovered private routes, and the provider advertises them only after helper firewall activation. Providing exit-node forwarding remains unimplemented |
| WireGuard crypto and framing | Swift implements encrypted Noise IKpsk2 fields, fixed initiation/response/cookie packet layouts, MAC1/MAC2, encrypted type-4/7/8 framing, Go-compatible padding/IP trimming, per-peer sessions, native Network.framework UDP, authenticated initiation/cookie retry, Go-cadence retries, overlapping-session rekey at 120 seconds, a 300-second reject-after window, and configured keepalive. All peer event, P2P, WUSP-control, and WUSP-transfer AsyncStreams are bounded to 128 queued items; transfer-frame overflow drops the oldest queued item and increments a diagnostic counter. Local authenticated UDP responders verify handshake, rekey, fragmented type-8 WUSP delivery, and transfer-queue overflow behavior; timer policy passes unit tests. Live Go-peer handshake/rekey, packet-level keepalive timing, responder/index lifecycle, and provider integration remain unverified |
| TCP service scan | Native Network.framework scanner probes one explicit IP literal at a time, with 128-port and 16-connection bounds; per-device UI action and loopback listener integration test pass, but the live tenant device directory is absent |
| ICMP ping | Native Darwin datagram ICMP probe, six bounded samples, average/loss result and compact chart; IPv4 and IPv6 loopback integration tests pass, but the live tenant device directory is absent |
| Local macOS telemetry and LAN discovery | Read-only native hostname/model/OS, uptime, memory, TCP, time/time-zone, IPv4/IPv6 capability, and interface/IP snapshot collector. Host telemetry uses Darwin APIs directly, with no shell or AppleScript. Private-LAN discovery returns canonical, deduplicated RFC1918 routes only from active physical non-loopback/non-point-to-point interfaces, validates contiguous masks, supports /32, and rejects more than 16 routes. The UI offers discovered routes only; the provider independently revalidates selections and derives egress/tunnel interfaces from current host state before helper activation and Go-compatible advertisement |
| Network Extension | Provider loads the registered config via shared Keychain, waits for a fresh authenticated handshake before configuring routes, then pumps IPv4/IPv6 packets through the encrypted peer transport. It fails closed on missing credentials, handshake timeout, or invalid settings. XcodeGen now declares a system-extension target, provider-class mapping, early `startSystemExtensionMode()` entry point, and `OSSystemExtensionRequest` activation with approval/reboot handling. Full Xcode project build, Apple-granted entitlements, provisioning, activation, and provider lifecycle are not verified |
| WireGuard transport-data packet engine | Per-peer session, UDP transport, rekey, and Network Extension packet read/write path are connected. Direct peer ingress now validates IPv4 source against that peer's assigned /32 before writing into the host packet flow; direct peer send errors fall back to the hub route, while a hub send error still fails the tunnel. Local authenticated handshake/rekey, packet-source policy, and route-builder tests pass, but provider packet-flow runtime, live Wantastic Go interoperability, and cleanup under actual macOS route changes remain unverified |
| P2P discovery and NAT traversal | Coordinator registration, peer discovery, authenticated punch orchestration, bounded target dialing, same-port UDP exchange, fresh WireGuard direct-session promotion, and four-minute stale-session retirement are present. Unit tests exercise punch-socket-to-WireGuard-session promotion and stale-session closure on loopback; the Network Extension provider route-selection path itself remains untested. NAT behavior against independent networks and live route switching/recovery remain unverified. |
| Service launch actions | Explicit Open actions create HTTP(S), RDP, or SSH URLs only when a matching service is discovered on a literal IP; URL policy is unit-tested. Launch depends on a registered macOS URL handler and was not interactively verified |
| Routing and DNS | Provider builds native split routes from AllowedIPs, adds endpoint host-route exclusions, assigns tunnel addresses, and routes the `wantastic` DNS suffix to configured resolvers with `wantastic` also configured as the search suffix for single-label MagicDNS names, matching Go's Darwin `domain wantastic` resolver. Swift network settings and Go resolver-file tests consume the same split-DNS fixture; duplicate DNS servers are removed in first-seen order. Network settings are unit-tested as values, but live route installation and resolution of tenant MagicDNS records are not verified without an entitled extension and live tenant |
| Firewall forwarding | A pure Swift `MacLocalAccessFirewallPlan` validates interface names, private prefixes, per-owner route bounds, conflicting egress mappings, and overlay overlap, then generates deterministic PF NAT/pass rules matching the existing Darwin Go rule layout. The provider exposes an opt-in bounded RPC; it independently validates selected routes, constructs the plan from live host interfaces, and uses `MacLocalAccessRouteCoordinator` to apply forwarding before advertisement and withdraw before cleanup. A separately built helper exposes constrained XPC operations for the fixed Wantastic anchor, forwarding sysctl, and a fixed native reboot request; the app bundle includes its LaunchDaemon manifest and an `SMAppService` registration/approval flow. XPC peer requirements pin the signing certificate and accept only the app or its network extension. The helper persists owned PF/forwarding state and supports rollback/recovery from that record, including after provider-process restart. Fake-backed tests cover interrupted forwarding writes, ownership checks, invalid state/token rejection, fixed PF arguments, restart cleanup, advertisement ambiguity, safe withdrawal, and reboot scheduling without invoking the OS reboot. Real macOS PF/sysctl, actual reboot, and signed XPC runtime behavior are still unverified; local-access activation remains gated on helper approval and trusted matching signatures. |
| Swift unit tests | 139 tests pass with `make test-swift`; `go test ./... -count=1` passes across the Go compatibility implementation. The target also type-checks the separately compiled Xcode host-app and system-extension source sets despite local Xcode being unavailable. Coverage includes Go-compatible WUSP codecs and fixtures, action replay/idempotency and identity-reuse rejection, async Operate dispatch and command allowlisting, fixed helper reboot scheduling, tenant-scoped factory reset with unrelated-Keychain preservation, encrypted WireGuard loopback FactoryReset response flow, bidirectional authenticated type-8 transfer transport/flood bounds, upload atomic commit, download chunk/ACK flow, bounded retransmission and abort, aggregate staging quota and cleanup, destination overwrite rejection, path confinement, plus the existing WireGuard/P2P/DNS/local-access tests. Network Extension provider lifecycle remains untested on a live entitled extension; live tenant sessions and external file picker access are not covered. |
| Signed, notarized release | Local UI app builds with a verified ad-hoc signature only. This Mac reports zero valid code-signing identities; no Apple Developer ID identity, Network Extension entitlement/profile, or notarization is available |

Do not distribute or rely on this build as a VPN client until the provider is
activated, shared-Keychain access and packet-flow routing are verified, tenant
MagicDNS records resolve, live Wantastic interoperability and production P2P/NAT
are proven, routes clean up safely, and entitlement-backed integration tests
pass on macOS.
